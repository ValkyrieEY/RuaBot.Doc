常见问题 ​

按「症状 → 原因 → 处理方式」组织。遇到问题先用页面右上角的搜索，搜日志里的关键词。

部署与启动 ​

启动后浏览器打不开控制台 ​

症状

页面打不开、连接被拒绝；或服务日志里出现：

text
bind: Address already in use

原因

  1. 8080 端口被别的程序占用；
  2. 服务器安全组 / 防火墙没有放通 8080；
  3. 服务其实没起来（例如数据库连不上，启动直接失败）。

处理方式

bash
# 1. 确认服务在跑
systemctl status xiaoyi-qq-c

# 2. 看端口有没有被占用
# Linux
ss -tlnp | grep 8080
# Windows（开发机）
netstat -ano | findstr 8080

端口被占用就改配置里的 admin_listen（例如换成 8080 之外的端口）后重启；是防火墙就放通端口；服务没起来就先看日志里的报错。

安装向导进不去 / 想重新走一遍向导 ​

症状

访问控制台直接进登录页，没有出现安装向导；或者想重装、重建管理员账号。

原因

安装向导只在首次启动（还没有初始化标记文件）时出现，安装完成后会写入标记文件，之后就一直走正常启动流程。

处理方式

顺序不能反

必须先停服务再删除标记文件，否则运行中的进程会把标记文件重新写回来。

bash
systemctl stop xiaoyi-qq-c          # 1. 先停服务
rm -f .installed                    # 2. 删除初始化标记（在程序目录里）
systemctl start xiaoyi-qq-c         # 3. 启动，会重新进入安装向导

重新走向导会重写配置文件，数据库里的业务数据不受影响，但请先确认你已经知道数据库连接信息。

程序必须从根目录启动 ​

症状

启动报错找不到配置文件 / 找不到插件目录 / 数据库迁移失败。

原因

配置、插件、迁移脚本都是按相对路径读取的，工作目录不对就会找不到。

处理方式

始终在程序所在目录启动，例如：

bash
cd /opt/xiaoyi_qq_c && ./xbot

用 systemd 管理时，服务单元里已经设好了工作目录，正常使用不用管。

机器人连接 ​

机器人一直显示离线 ​

症状

机器人详情页状态是离线；日志里反复出现重连。

原因

  1. AppID / AppSecret 填错或已重置；
  2. 服务器访问不了平台网关（网络受限、DNS 异常）；
  3. 平台主动断开连接做轮换 —— 这种情况框架会静默重连，日志里会写明是轮换，不是故障。

处理方式

先看机器人详情页的日志 Tab：如果看到「平台轮换连接，静默重连」，属于正常行为，等几秒会自动恢复；如果是鉴权失败，回到「添加机器人」核对凭据；如果一直连不上，检查服务器出网是否正常。

群里发消息机器人不回复 ​

症状

私聊正常，群里 @ 机器人也没反应；或者只有 @ 了才回。

原因

QQ 官方平台默认只推送 @ 机器人的消息。要收到群里全部消息，需要群主开启「群全量消息」授权。

处理方式

  1. 确认机器人已在群里、且状态在线；
  2. 在控制台插件市场安装「全量申请」插件，生成授权深链发给群主，让群主在 QQ 里点开授权；
  3. 授权后群里未 @ 的消息也会推给机器人。

Webhook 模式收不到平台事件 ​

症状

用 Webhook 方式接入，平台上配置好了回调地址，但机器人收不到任何消息。

原因

回调地址里的域名是动态推导的：没配公网域名时会退化成当前请求的 Host（可能是内网地址或 localhost），平台自然回调不到。

处理方式

在「平台设置 → 站点」里显式配置回调协议与公网域名，再用控制台给出的回调地址回填到平台。反向代理要转发 Host 头。详见 回调地址与公网域名。

平台权限 ​

接口返回「应用无接口访问权限」 ​

症状

调用群信息、群成员、禁言、入群审批等能力时失败，返回内容里带：

json
{"message":"应用无接口访问权限","code":11253}

原因

该接口属于平台需要单独开通/加白名单的能力，当前机器人还没有权限。

处理方式

到 QQ 开放平台为该机器人开通对应能力。插件的日志里会原样保留这条错误，所以先看机器人的日志页确认是哪一步被拒，再对照平台的权限列表去开通。

按钮点了没反应 / 提示无权限 ​

症状

群里播报带按钮，点击后没有任何反应，或者客户端提示无权限。

原因

绝大多数情况是按钮本身没有被平台接受：按钮的权限、类型配置不正确时，客户端会直接拒绝点击，框架收不到任何回调（所以日志里什么都看不到）。

处理方式

  1. 确认这是 QQ 官方平台的机器人（按钮只在 QQ 官方可用，其它平台发送时不会渲染成按钮，需要用文字指令完成同样的事）；
  2. 确认群管类插件的「使用按钮」开关是开的；
  3. 点不动时，直接用文字指令完成同样的事（例如回复「同意 1」），不影响功能；
  4. 如果是插件开发者、自己在生成按钮，检查按钮 JSON 的字段是否符合平台规范（按钮类型、权限类型、必填的兜底文案）。

禁言 / 踢人失败 ​

症状

群里发指令后提示操作失败。

原因

  1. 机器人不是群管理员；
  2. 该群管理接口未在平台开通。

处理方式

让群主把机器人设为群管理员；再去 QQ 开放平台确认相关能力已开通。操作结果会记进插件的审计记录，带失败原因。

插件 ​

上传插件报「无法读取插件元数据」 ​

症状

管理后台上传插件包时被拒绝。

原因

插件没有导出元数据符号（通常是没有用官方注册宏），或者二进制文件已损坏。

处理方式

用官方 SDK 的注册宏（BOT_REGISTER_PLUGIN 系列）重新编译。自己写构建脚本时，注意不要漏掉注册宏所在的源文件。

插件加载失败 / 提示 ABI 不兼容 ​

症状

日志里出现插件被拒绝加载，提示版本不匹配。

原因

插件与框架的二进制接口版本不匹配（用更新的 SDK 编的插件放到更旧的框架上）。

处理方式

升级框架，或改用与当前框架版本匹配的 SDK 重新编译插件。规则见 ABI 与兼容规则。

插件装上去了但完全不触发 ​

症状

插件显示已启用，群里发消息没有任何反应。

原因

按可能性排序：

  1. 插件没有声明订阅该事件（事件掩码没打开）；
  2. 插件没装到这台机器人上（装到别的机器人去了）；
  3. 群消息收不到 —— 需要全量消息授权（见上文）；
  4. 插件的触发条件没命中（例如只处理 @ 消息，而这条消息没 @ 机器人）。

处理方式

到机器人详情页确认「插件」Tab 里该插件已启用；查看插件自己的日志输出；用「回声」这类最小插件验证机器人本身能不能收发消息，快速区分是插件问题还是接入问题。

提示插件位不足 ​

症状

安装插件被拒绝，提示超出配额。

原因

套餐里的插件位用完了。

处理方式

卸载不用的插件，或升级套餐。当前配额可以在订阅中心看到。

插件面板能打开但操作都失败 ​

症状

插件面板页面能显示，但保存配置、执行动作都提示失败。

原因

  1. 插件没有安装（绑定）到这台机器人；
  2. 插件被停用；
  3. 面板会话过期（面板地址里带一次性令牌，长时间停留会失效）。

处理方式

到机器人详情页的「插件」Tab 确认已安装且启用；关掉面板重新打开即可换新令牌。

账号与订阅 ​

注册时提示 QQ 号无效 ​

原因

注册必须填 QQ 号，且格式被限定为 5–15 位、不以 0 开头的纯数字。

处理方式

填正确的 QQ 号即可。如果服务商要求邮箱验证，按提示去邮箱点验证链接。

忘记密码收不到邮件 ​

原因

服务商没有配置邮件发送（SMTP），或关闭了自助找回密码。

处理方式

联系服务商重置，或在有管理员权限的情况下到「平台设置 → 邮件」里把 SMTP 配好。生产环境下即便配置正确，也不会把重置链接直接显示在页面上，而是发到邮箱。

机器人回复变慢 ​

处理方式

先看控制台的「服务器监控」页：CPU、内存、进程占用、运行时长、消息吞吐都在这里。多数情况是单机负载偏高或某个插件在等外部接口，可以结合机器人日志定位。
