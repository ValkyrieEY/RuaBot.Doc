QQ OneBot 11 🔄 ​

OneBot 11 不是某个具体程序，而是一套协议。你需要先有一个实现端（NapCat、Lagrange、go-cqhttp 等）负责登录 QQ、收发消息，再让它用反向 WebSocket 连到 Xiaoyi_QQ_V4。

这条路的代价是你要自己部署并维护实现端；回报是群管理类能力走 OneBot 标准接口就能用，不受 QQ 开放平台的权限审批限制。

1. 先部署实现端并登录 ​

在你自己的机器上部署一个 OneBot 11 实现端，选哪个由你决定：

实现端说明
NapCat常见的 QQ 实现端
Lagrange常见的 QQ 实现端
go-cqhttp老牌实现端

部署方式、登录方式、扫码 / 滑块验证这些都在实现端自己的文档里，本框架不参与。先把实现端跑起来、QQ 登录成功，再往下走。

2. 在控制台添加机器人 ​

登录控制台，进入「我的机器人」，点「添加机器人」：

  • 第一步：平台选 qq_onebot（OneBot 11）
  • 第二步：填机器人的名称（只用于你在控制台里区分它），以及可选的 AccessToken
  • 连接方式：选 反向 WebSocket

提交后机器人立即上线，不需要重启服务。

3. 记下反向 WS 地址 ​

创建完成后，控制台会给出一个反向 WS 地址，形如：

text
ws://<你的服务器>:8081/...

注意这里是 8081，不是控制台的 8080。两个端口的用途不同，详见 回调地址与公网域名。

地址在创建后才显示

这个地址里带有机器的标识信息，请到机器人详情页对照实际显示值复制，不要按上面这行的形状自己拼。

4. 回填到实现端 ​

打开实现端的配置，找到「反向 WebSocket」相关设置：

  • 把第 3 步复制的地址填进反向 WS 地址（不同实现端字段名不一样，认准 reverse / 反向 字样）
  • 保存并让实现端重连

如果控制台里这台机器人填了 AccessToken，实现端侧也要填上相同的值，两边一致才能连上。

控制台字段说明
AccessToken可选。填了就必须和实现端配置一致

5. 确认在线 ​

回机器人详情页「设置」Tab，确认：

  • 适配器显示为 qq_onebot
  • 连接方式显示为反向 WebSocket
  • 状态显示为在线

状态在线之后，在群里发条消息，机器人的「数据」Tab 里应该能看到消息记录。

截图占位

截机器人详情页，露出控制台给出的反向 WS 地址字段（域名可打码成 <你的服务器>），以及「设置」Tab 里的适配器与状态。

6. 能力差异 ​

不同适配器支持的能力不一样，插件里通过能力码（capability）调用时框架会做适配：

能力在 OneBot 11 上
按钮消息不渲染按钮，需改用文字指令
Markdown 消息不渲染富文本，正文按纯文本发出
禁言 / 踢人等群管理可用，走 OneBot 标准接口
入群审批不可用（QQ 官方专属能力）

写插件时如果不确定某个能力码在 OneBot 上的表现，可以查 平台能力码；机器人在线时，详情页「设置」Tab 底部也会列出它当前支持的能力。

7. 连不上怎么查 ​

症状：状态一直是离线，控制台没有连接成功的记录 ​

  • 原因：实现端的反向 WS 地址填错，尤其是端口写成了 8080。
  • 处理方式：确认地址里是 8081；确认实现端所在机器能访问到框架所在机器的 8081 端口。

症状：实现端日志报 401 / 鉴权失败 ​

  • 原因：控制台里配了 AccessToken，但实现端没填或填得不一样。
  • 处理方式：两边改成完全一致；不需要鉴权时把控制台的 AccessToken 清空、实现端侧也留空。

症状：连接建立后又立刻断开，反复重连 ​

  • 原因：网络中间设备掐断长连接，或实现端和框架版本不匹配。
  • 处理方式：先看机器人「日志」Tab 里的断开原因；确认实现端是最新版本；检查链路上有没有会中断空闲连接的代理。

症状：连接正常，但收不到群消息 ​

  • 原因：QQ 登录掉线，或实现端没订阅对应的上报事件。
  • 处理方式：去实现端的界面确认 QQ 仍然在线；确认实现端的事件上报开关是打开的。

需要抓日志时 ​

优先看机器人详情页的「日志」Tab。要在服务器上看：

bash
# Linux：确认 8081 端口在监听
ss -lntp | grep 8081
powershell
# Windows：确认 8081 端口在监听
Get-NetTCPConnection -LocalPort 8081 -State Listen
