QQ 官方：Webhook 回调 📮 ​

Webhook 模式和 WebSocket 网关模式接入的是同一类机器人，区别只在谁发起连接：网关模式是框架主动连平台，回调模式是平台主动把事件推给你。

因此这页的重点不是「怎么配机器人」，而是「回调地址怎么来、填到哪里去」。如果你没有公网域名，直接用 WebSocket 网关 更省事。

1. 和网关模式的差异一览 ​

对比项WebSocket 网关Webhook 回调
谁发起连接框架连平台平台回调你
公网域名不需要必须
控制台里的配置只填凭据与环境凭据、环境，外加一个回调地址要填回平台
机器人详情页常规 5 个 Tab多出一个「事件转发」Tab
适用场景绝大多数情况已有稳定公网域名、希望回调直连

2. 先配好公网域名 ​

回调地址里的协议与域名不是手填的，而是取自「平台设置 → 站点」里的两个配置：

配置项作用
webhook_protocol回调地址用什么协议，决定是 http 还是 https
webhook_domain回调地址用哪个域名

务必配公网域名

如果这两个值没配，回调地址会退化成当前浏览器访问控制台所用的 Host。那样生成出来的地址只在你本机网络里有效，QQ 开放平台根本回调不到，表现为「事件一直收不到」。

配域名、上 HTTPS、反向代理这些事，完整步骤见 回调地址与公网域名。

3. 在控制台添加机器人 ​

进入「我的机器人」，点「添加机器人」：

  • 第一步：平台选 qq_official
  • 第二步：填名称、AppID、AppSecret、环境（production 或 sandbox）
  • 连接方式：选 Webhook 回调

提交后机器人立即上线，不需要重启服务。

4. 把回调地址填回 QQ 开放平台 ​

选完 Webhook 后，控制台会弹出一个回调地址，形如：

text
{协议}://{域名}/api/webhooks/adapters/qq_official/{机器人UUID}

其中 {协议} 与 {域名} 就是第 2 步里配的 webhook_protocol 与 webhook_domain，{机器人UUID} 是这台机器人在控制台里的唯一标识。

把这个地址原样复制，填到 QQ 开放平台的回调配置里。注意：

  • 不要漏掉末尾的机器人 UUID 那一段
  • 改过 webhook_domain 之后，地址会变，需要回平台上重新填一次

5. 确认生效 ​

回到机器人详情页：

  • 「设置」Tab 里的连接方式应显示为 Webhook 回调
  • 页面上会多出一个「事件转发」Tab，这是 Webhook 模式独有的

事件转发 Tab 用来查看 / 配置事件往哪里转发。如果你在「设置」里没看到它，说明当前不是 Webhook 模式。

截图占位

截两处：一是选 Webhook 后弹出回调地址的对话框（地址可打码，露出结构即可）；二是机器人详情页顶部 Tab 栏，露出「事件转发」这个多出来的 Tab。

6. 收不到回调怎么查 ​

症状：QQ 开放平台提示回调地址校验失败 ​

  • 原因：回调地址填错，或域名解析不到、证书不对。
  • 处理方式：在浏览器里直接打开那个回调地址对应的域名，确认能解析、HTTPS 证书有效；再对照控制台弹出的地址逐字符核对。

症状：平台上校验通过，但机器人收不到任何事件 ​

  • 原因：回调地址退化成当前访问的 Host（webhook_domain 没配），或者反向代理没把 Host 头透传。
  • 处理方式：到「平台设置 → 站点」把 webhook_domain 配成真实公网域名，重新生成地址并回填平台；再按 回调地址与公网域名 检查反向代理配置。

症状：换个浏览器 / 换台电脑登录控制台，回调地址就变了 ​

  • 原因：同样是 webhook_domain 没配，地址跟着访问用的 Host 走。
  • 处理方式：配好 webhook_domain 之后地址就固定了。

症状：反向代理后所有回调都是 404 ​

  • 原因：代理只转发了部分路径，回调路径没放行。
  • 处理方式：确认代理放行了管理面端口上的 /api/webhooks/ 路径，端口用途区分见 回调地址与公网域名。
nginx
# Nginx：把回调路径转发到管理面端口（示例，按你的实际监听地址调整）
location /api/webhooks/ {
    proxy_pass http://<你的服务器IP>:8080;     # 框架与代理同机时填回环地址
    proxy_set_header Host $host;              # 必须透传 Host
    proxy_set_header X-Real-IP $remote_addr;
}
