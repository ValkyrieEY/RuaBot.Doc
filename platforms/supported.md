# 支持的平台

> **你会学到**：V3 支持哪些平台、各自怎么接入、什么是连接模式。

V3 通过**适配器**接入各大即时通讯平台。得益于 [XUBP 协议](../xubp/overview)，同一份插件在所有平台通用，你只需关心接入配置。

## 九大支持平台

| 平台 | 适配器 | 典型连接模式 |
|------|--------|-------------|
| **QQ 官方** | QQ 官方机器人 | Webhook 回调 |
| **QQ（OneBot）** | OneBot v11 | 反向 WebSocket |
| **Telegram** | Telegram Bot | 长轮询 |
| **Discord** | Discord Bot | 正向 WebSocket |
| **KOOK** | KOOK Bot | WebSocket |
| **飞书** | 飞书机器人 | Webhook 回调 |
| **钉钉** | 钉钉机器人 | Webhook 回调 |
| **微信公众号** | 公众号 | Webhook 回调 |
| **企业微信** | 企业微信 | Webhook 回调 |

::: tip 平台会持续增加
V3 的适配器架构支持扩展新平台。如有新的平台需求，联系平台方。
:::

## 连接模式说明

不同平台推送事件的方式不同，V3 支持四种连接模式：

| 模式 | 方向 | 工作方式 | 典型平台 |
|------|------|---------|---------|
| **Webhook 回调** | 平台 → 我们 | 平台主动把事件 POST 到我们的回调地址 | QQ 官方、飞书、钉钉 |
| **正向 WebSocket** | 我们 → 平台 | 我们连到平台的 WS 网关接收事件 | Discord |
| **反向 WebSocket** | 平台 → 我们 | 平台的客户端连到我们开放的 WS | OneBot、Lagrange |
| **长轮询** | 我们 → 平台 | 我们反复请求平台拉取新事件 | Telegram |

::: tip 插件无感知
连接模式是**适配器层面**的事，插件完全不用关心。无论平台用哪种模式接入，插件看到的都是统一的 [XUBP 事件](../xubp/events)。
:::

## 接入一个平台

在 V3 后台接入某个平台，大致流程：

1. **创建机器人**：在用户控制台创建一个机器人实例，选择对应平台适配器。
2. **填写平台凭证**：填入该平台的应用 ID、Token、Secret 等（各平台不同）。
3. **配置连接**：
   - Webhook 类：把 V3 生成的回调地址填到平台后台。
   - WebSocket 类：确认 V3 能连到平台，或平台能连到 V3。
   - 轮询类：填好 Token 即可。
4. **启用机器人**：启动后开始接收事件。

每个平台的具体凭证获取方式，参考各平台官方文档。

::: warning Webhook 需要 HTTPS
QQ 官方、飞书等 Webhook 类平台，要求回调地址必须是**公网可访问的 HTTPS**。请先配好 [Nginx + SSL](../deploy/nginx)。
:::

## 各平台事件支持

不同平台能提供的事件类型有差异。完整的事件支持情况见 [事件类型 · 跨平台映射](../xubp/events#跨平台事件映射)。

简单说：

- **消息类**（群/私聊）：所有平台都支持。
- **交互/按钮**：QQ 官方、Discord、Telegram 等支持。
- **表情表态**：QQ 官方、Discord 等支持。
- **频道相关**：QQ 官方、Discord 等支持。

不支持的类型，适配器会在对应平台标注 "—"，未来版本可能补齐。
