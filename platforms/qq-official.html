QQ 官方：WebSocket 网关 🔗 ​

这是接入 QQ 官方机器人推荐的方式：框架主动去连 QQ 开放平台的网关，你不需要准备公网域名，也不需要配任何回调地址。适合绝大多数部署在普通云主机上的情况。

读完这页你能做到：在 QQ 开放平台拿到凭据，在控制台把机器人创建出来，并确认它显示为在线。

1. 在 QQ 开放平台创建机器人 ​

先到 QQ 开放平台完成机器人应用的创建，这一步在平台侧做，不在本框架里。创建完成后你需要从平台上取两样东西：

需要的东西说明
AppID机器人应用的唯一标识
AppSecret机器人应用的密钥，填进控制台后请妥善保管

同时建议在平台上把机器人需要的权限先配好（不同机器人能开的权限不一样，以平台页面上的可选项为准）。

前置条件不满足会连不上

机器人必须先在 QQ 开放平台配置完成，并且已经被拉进目标群，否则框架即使连上了网关，也收不到任何群消息。

2. 在控制台添加机器人 ​

登录控制台，进入「我的机器人」，点「添加机器人」。

  • 第一步：平台选 qq_official（QQ 官方）
  • 第二步：填下面这些字段
字段填什么
名称给机器人起个名字，只用于你在控制台里区分它，随意填
AppID第 1 步从 QQ 开放平台拿到的值
AppSecret第 1 步从 QQ 开放平台拿到的值
环境填 production（正式）或 sandbox（沙箱），要和平台上机器人所处的环境一致

填完提交即可，机器人创建后立即上线，不需要重启服务。

3. 连接方式选 WebSocket 网关 ​

在向导的连接方式一步选「WebSocket 网关」。

选它的好处是：

  • 不需要填回调地址，框架会主动连上平台
  • 不需要公网域名，服务器在内网也能跑
  • 防火墙只需要放行出站，不用对外开放入口

如果你确实需要平台主动回调你（例如有固定公网域名并且希望走回调），改看 QQ 官方：Webhook 回调。

4. 确认在线 ​

创建完成后进入机器人详情页，看「设置」Tab：

  • 适配器应显示为 qq_official
  • 连接方式应显示为 WebSocket 网关
  • 状态应显示为在线

再切到「日志」Tab，正常情况下能看到连接建立的相关输出。如果状态一直不在线，按下一节的清单逐条排查。

截图占位

截机器人详情页「设置」Tab，重点露出适配器、连接方式、状态三行以及下方的支持能力列表。

5. 让机器人收到群里的消息 ​

机器人进了群不等于能收到全部消息。QQ 官方默认只在消息 @ 到机器人时分发给它。

要让机器人收到群内全量消息，需要在 QQ 开放平台为机器人取得「群全量消息」授权。这一步在平台侧完成，通常需要走申请流程。

用「全量申请」插件生成授权深链

控制台的插件市场里有名为全量申请的插件，它能生成授权用的深链，省去你在平台页面里找入口的麻烦。装上并打开它的插件面板即可使用，安装方式见 插件市场与安装。

6. 连不上怎么查 ​

按「症状 / 原因 / 处理方式」逐条对照。

症状：状态一直是离线，日志里反复出现连接失败 ​

  • 原因：AppID / AppSecret 填错，或复制时带了首尾空格。
  • 处理方式：到机器人详情页「设置」Tab 重新核对凭据；如果拿不准，直接在 QQ 开放平台重新生成一次 AppSecret 再填。

症状：状态在线，但群里发消息机器人没反应 ​

  • 原因：机器人没被拉进群，或者消息没有 @ 到机器人，而「群全量消息」授权又没拿到。
  • 处理方式：先把机器人拉进群，在群里 @ 它试一次；如果 @ 有反应、不 @ 没反应，说明缺的是全量消息授权，用「全量申请」插件走一遍授权。

症状：使用了沙箱环境，但只有部分人能用 ​

  • 原因：环境和平台上机器人所处的环境对不上。
  • 处理方式：确认控制台里「环境」字段填的是 production 还是 sandbox，与 QQ 开放平台上一致即可。

症状：添加机器人时被拒绝，提示和额度有关 ​

  • 原因：机器人数已经用满套餐额度。
  • 处理方式：删掉不用的机器人，或升级套餐，见 订阅 · 卡密 · 充值。

需要抓日志时 ​

日志在机器人详情页的「日志」Tab 里能直接看，不用登服务器。如果确实要在服务器上看：

bash
# Linux：跟踪服务日志（具体路径以你的部署方式为准）
journalctl -u xiaoyi-qq -f
powershell
# Windows：在 PowerShell 中查看服务状态
Get-Service | Where-Object { $_.Name -like '*xiaoyi*' }
