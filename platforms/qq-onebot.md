# QQ OneBot 11 🔄

OneBot 11 不是某个具体程序，而是一套协议。你需要先有一个**实现端**（NapCat、Lagrange、go-cqhttp 等）负责登录 QQ、收发消息，再让它用**反向 WebSocket** 连到 Xiaoyi_QQ_V4。

这条路的代价是你要自己部署并维护实现端；回报是群管理类能力走 OneBot 标准接口就能用，不受 QQ 开放平台的权限审批限制。

## 1. 先部署实现端并登录

在你自己的机器上部署一个 OneBot 11 实现端，选哪个由你决定：

| 实现端 | 说明 |
|---|---|
| NapCat | 常见的 QQ 实现端 |
| Lagrange | 常见的 QQ 实现端 |
| go-cqhttp | 老牌实现端 |

部署方式、登录方式、扫码 / 滑块验证这些都在实现端自己的文档里，本框架不参与。**先把实现端跑起来、QQ 登录成功**，再往下走。

## 2. 在控制台添加机器人

登录控制台，进入「我的机器人」，点「添加机器人」：

- 第一步：平台选 `qq_onebot`（OneBot 11）
- 第二步：填机器人的**名称**（只用于你在控制台里区分它），以及可选的 `AccessToken`
- 连接方式：选 **反向 WebSocket**

提交后机器人立即上线，不需要重启服务。

## 3. 记下反向 WS 地址

创建完成后，控制台会给出一个反向 WS 地址，形如：

```text
ws://<你的服务器>:8081/...
```

注意这里是 **8081**，不是控制台的 8080。两个端口的用途不同，详见 [回调地址与公网域名](/platforms/callback)。

::: warning 地址在创建后才显示
这个地址里带有机器的标识信息，请到机器人详情页对照实际显示值复制，不要按上面这行的形状自己拼。
:::

## 4. 回填到实现端

打开实现端的配置，找到「反向 WebSocket」相关设置：

- 把第 3 步复制的地址填进**反向 WS 地址**（不同实现端字段名不一样，认准 reverse / 反向 字样）
- 保存并让实现端重连

::: danger AccessToken 是**必填**的，两边必须一致
控制台里这台机器人的 **AccessToken**（创建机器人时的密码框字段）**必须填**，
并在实现端侧填上**完全相同**的值，否则连不上。

**没填 AccessToken 的机器人会被直接拒绝接入**（返回 403）—— 这是有意的：
8081 端口如果允许无凭据连接，任何能访问到它的人都能冒充你的机器人收发消息。
:::

| 控制台字段 | 说明 |
|---|---|
| AccessToken | **必填**。必须和实现端配置逐字一致（区分大小写） |

## 5. 确认在线

回机器人详情页「设置」Tab，确认：

- 适配器显示为 `qq_onebot`
- 连接方式显示为反向 WebSocket
- 状态显示为在线

状态在线之后，在群里发条消息，机器人的「数据」Tab 里应该能看到消息记录。

::: details 截图占位
截机器人详情页，露出控制台给出的反向 WS 地址字段（域名可打码成 `<你的服务器>`），以及「设置」Tab 里的适配器与状态。
:::

## 6. 能力差异

不同适配器支持的能力不一样，插件里通过能力码（capability）调用时框架会做适配：

| 能力 | 在 OneBot 11 上 |
|---|---|
| 按钮消息 | 不渲染按钮，需改用文字指令 |
| Markdown 消息 | 不渲染富文本，正文按纯文本发出 |
| 禁言 / 踢人等群管理 | 可用，走 OneBot 标准接口 |
| 入群审批 | 不可用（QQ 官方专属能力） |

写插件时如果不确定某个能力码在 OneBot 上的表现，可以查 [平台能力码](/reference/capabilities)；机器人在线时，详情页「设置」Tab 底部也会列出它当前支持的能力。

## 7. 连不上怎么查

### 症状：状态一直是离线，控制台没有连接成功的记录

- **原因**：实现端的反向 WS 地址填错，尤其是端口写成了 8080。
- **处理方式**：确认地址里是 **8081**；确认实现端所在机器能访问到框架所在机器的 8081 端口。

### 症状：实现端日志报 401 / 403 / 404

- **401**：AccessToken 不匹配。两边改成**完全一致**（区分大小写）。
- **403**：这台机器人**没有配 AccessToken**。去机器人设置里补一个再重连。
- **404**：连接地址的**最后一段**不是这台机器人的 UUID。到机器人详情页复制「反向 WS 地址」，
  别自己拼；确认实现端连的是 8081（不是 8080）。
- **400**：地址里完全没有 UUID —— 同上，从控制台复制。

### 症状：连接建立后又立刻断开，反复重连

- **原因**：网络中间设备掐断长连接，或实现端和框架版本不匹配。
- **处理方式**：先看机器人「日志」Tab 里的断开原因；确认实现端是最新版本；检查链路上有没有会中断空闲连接的代理。

### 症状：连接正常，但收不到群消息

- **原因**：QQ 登录掉线，或实现端没订阅对应的上报事件。
- **处理方式**：去实现端的界面确认 QQ 仍然在线；确认实现端的事件上报开关是打开的。

### 需要抓日志时

优先看机器人详情页的「日志」Tab。要在服务器上看：

```bash
# Linux：确认 8081 端口在监听
ss -lntp | grep 8081
```

```powershell
# Windows：确认 8081 端口在监听
Get-NetTCPConnection -LocalPort 8081 -State Listen
```
