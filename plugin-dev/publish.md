# 发布与上架

> **你会学到**：怎么把写好的插件上传到平台、定价、上架到市场、赚取分成并提现。

## 开发者中心

V3 内置**开发者中心**。注册成为开发者后，你可以：

- 上传和管理插件
- 管理插件版本
- 设置价格和上架状态
- 查看销量和收益
- 申请提现

## 上传插件

1. 按插件目录结构打包好（至少 `meta.yaml` + `main.py`）。
2. 在开发者中心点「上传插件」，提交 zip 包。
3. 平台校验 `meta.yaml` 和入口文件，通过后插件进入「未上架」状态。

::: tip code 要稳定
上传时 `meta.yaml` 的 `code` 决定插件身份。**一旦确定不要改**——后续更新都用同一个 `code`，递增 `version` 即可。改 `code` 会被当成全新插件，历史销量和绑定丢失。
:::

## 版本管理

每次上传会创建一个新版本：

- `meta.yaml` 的 `version` 必须递增（语义化版本，如 `1.0.0` → `1.0.1`）。
- 客户可保持在旧版本或升级到新版本。
- 建议在 `description` 或更新日志里写清楚每个版本改了什么。

## 定价与上架

新插件默认 `allow_purchase: false`（**不上架**）。确认没问题后再上架：

| 设置 | 说明 |
|------|------|
| 价格 | `0` = 免费；>0 = 付费，客户购买后才能装 |
| 允许购买 | 开启后插件出现在市场，可被购买 |
| 分类 | `game` / `system` / `tool` / `fun` / `social` / `ai` / `other` |
| 隐藏 | 内部插件可设为隐藏，不在市场展示 |

::: warning 默认不上架
为避免误传或有问题的插件直接进入市场，**新上传的插件默认不上架**。你需要主动开启「允许购买」。
:::

## 审核机制

平台管理员会对上架的插件进行**审核**：

- 审核内容通常包括：功能是否正常、是否有恶意行为、是否合规。
- 审核通过后插件才会在市场正式可见。
- 审核未通过会给出原因，修改后重新提交。

## 收益与分成

客户购买付费插件产生的收入，按**平台与开发者的分成比例**结算：

- 每笔购买记录分成，开发者份额进入开发者余额。
- 你可以在开发者中心查看收益明细（哪个客户、买了哪个插件、分成多少）。
- 收益可累积，达到提现门槛后申请提现。

## 提现

- 开发者中心申请提现，将余额提现到你的收款账户。
- 平台审核提现申请后处理打款。
- 具体提现门槛、到账时间、分成比例由平台运营方配置。

## 上架检查清单

发布前过一遍这个清单：

- [ ] `meta.yaml` 的 `code` 稳定、`version` 已递增
- [ ] `events` 只订阅必要的事件类型
- [ ] `setting.json` 的字段都有合理的 `default` 和 `label`
- [ ] 主流程用 `context.reply()` / `context.sender_id` 等统一接口（跨平台）
- [ ] 平台特有功能做了降级处理
- [ ] 没有硬编码的测试数据 / 密钥
- [ ] 异常有 try/except，不会让插件整个崩掉
- [ ] `description` 写清楚了功能和用法
