# 目录结构与打包

这页讲清楚插件在服务器上长什么样、你上传的压缩包会被怎么解包。读完你能自己判断「我这个包能不能传上去」「面板文件为什么没生效」。

## 插件在服务端的运行目录

框架把每个插件放在以**插件编码**命名的目录下：

```text
plugins/
├── echo/                  # 插件编码 = echo
│   └── echo.so            # 插件本体（保留你上传时的文件名）
├── panel_demo/
│   ├── panel_demo.so      # 插件本体
│   └── web/               # Web 面板静态资源（只有带面板的插件才有）
│       ├── index.html     # 面板入口，名字由元数据的 web_entry 指定
│       └── assets/…       # 面板自带的 CSS / JS / 图片
└── .upload/               # 上传中转目录（读取元数据用，无需关心）
```

要点：

- 目录名固定为**插件编码**（`meta` 里的 `code`），不是文件名；
- 插件本体的文件名沿用你上传时的名字（会被净化掉路径分隔符）；
- `web/` 目录**可选**：插件可以只有设置项（走控制台的 schema 配置抽屉），完全不需要面板；
- 面板是**相对路径**加载的，`web_entry` 写 `index.html` 就指 `plugins/<code>/web/index.html`。

## 上传的 zip 里必须有什么

管理后台上传时接受 `.so`、`.dll` 或 `.zip`。zip 的解包规则很简单：

| zip 内的条目 | 是否采用 | 说明 |
| --- | --- | --- |
| 任意层级的 `.so` / `.dll` | 取**第一个** | 插件本体；同名的多个只会用第一个 |
| 以 `web/` 开头的条目 | 全部采用 | 落盘到 `plugins/<code>/web/` 下（自动剥掉 `web/` 前缀） |
| 其它文件（`README.md`、源码、`manifest.json`…） | 忽略 | 不会落盘，也不会报错 |

同时支持**直接上传裸 `.so`**（不打 zip）：此时视为只有插件本体，没有面板资源。

::: tip 打包约定
- 一个包 = 一个插件；
- 面板入口建议就叫 `web/index.html`，这是最常见的写法；
- 面板入口的默认值：如果 zip 里带了 `web/` 而元数据没声明 `web_entry`，框架会按 `index.html` 处理。
:::

面板目录内**单个文件不能超过 8 MB**（加载时限制），面板资源请保持精简。

## 插件分类规范

插件的 `CATEGORY`（注册宏第 5 个参数）决定它在插件市场里归到哪个标签页。**只有下面 8 个是规范集合**：

| 分类 | 适合放什么 |
| --- | --- |
| `tool` | 工具类：查询、翻译、提醒、签到统计 |
| `fun` | 娱乐类：表情包、语录、随机图 |
| `game` | 游戏类：群内小游戏、抽卡 |
| `ai` | AI 类：对话、绘图、语音合成 |
| `social` | 社交类：欢迎、名片、群互动 |
| `media` | 媒体类：点歌、视频解析、图片处理 |
| `admin` | 管理类：违禁词、链接拦截、禁言踢人 |
| `other` | 兜底分类 |

**不在集合内的分类会被自动归到 `other`**（上传时会写入一条提示日志）。所以 `CATEGORY` 直接填上面表里的英文单词，别填中文或自造标签。

## 插件 logo 的三种来源

框架读取 logo 的顺序是**从优先到兜底**：

| 优先级 | 来源 | 做法 |
| --- | --- | --- |
| 1（最高） | 内嵌字节 | 导出 `bot_plugin_logo_data()` / `bot_plugin_logo_size()`，用 `BOT_PLUGIN_LOGO_EMBED(kLogo, sizeof(kLogo) - 1)` 一行搞定；字节随动态库一起分发，**无需外链、不怕图床挂** |
| 2 | 网络 URL | 元数据 `LOGO` 填 `https://…`，市场卡片直接外链显示 |
| 3 | 本地文件 | 元数据 `LOGO` 填相对 `.so` 目录的路径（如 `logo.png`）；上传时框架会读取文件字节入库 |

::: details 说明
- 同时导出 `data` 与 `size` 且 `size > 0` 时，内嵌字节优先于元数据里的 `LOGO` 字符串；
- 本地文件路径若是相对路径，基准是插件动态库所在目录；绝对路径也能用，但不利于分发，不推荐；
- 支持的格式：PNG / JPG / SVG / ICO 等原始字节。
:::

**推荐尺寸**：市场卡片与详情页都按**正方形**展示 logo，建议提供正方形图（例如 128×128 或 256×256 的 PNG，或矢量 SVG）。用现成的框架示例写法最省事——`echo` 与 `intercept` 都用的是一个 64×64 的内嵌 SVG。

## 重新上传同一编码的插件

- 允许：会覆盖同名插件的记录与文件，**上传即热加载**，已经装了它的机器人立刻用上新版本；
- `web/` 目录内的文件会**整体替换**（上传带 `web/` 的包时先清空旧目录再写入），别指望残留旧文件；
- 版本号（`VERSION`）只是展示与识别用，不影响覆盖逻辑。
