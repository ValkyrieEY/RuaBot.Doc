# 为什么是 Xiaoyi_QQ_V4

Xiaoyi_QQ_V4 是一套**自托管的 QQ 机器人框架**：你自己在服务器上跑起来，接上 QQ 官方机器人或 OneBot 11 实现端，然后通过网页控制台管理机器人、安装插件、查看运行数据。

这页讲清楚三件事：它由什么组成、能做什么、以及为什么这样设计。

## 它是什么

一句话：**一个可执行文件 + 一个数据库，就是一套完整的机器人平台。**

| 组成部分 | 说明 |
| --- | --- |
| 框架本体 | 单个 C++ 可执行文件，包含管理接口、适配器、插件运行时与前端页面 |
| 数据库 | 一个 PostgreSQL 实例，保存用户、机器人、插件绑定、消息记录等业务数据 |
| 控制台 | 内嵌在框架里的网页界面，默认监听 `8080` 端口 |
| 插件 | 独立的 `.so` 文件，在框架进程内运行，可单独安装到某台机器人 |
| 云编译服务（可选） | 独立的小程序，把插件源码编译成可上架的插件包，供不会配编译环境的用户自助打包 |

::: tip 不需要的东西
不需要 Redis、不需要消息队列、不需要单独部署前端、不需要 Node.js 运行时。
:::

## 它由哪几部分组成

从使用者角度看，只有三层：

```text
        浏览器
           │  管理控制台（用户 / 管理员）
           ▼
   Xiaoyi_QQ_V4 框架进程
     ├── 管理面      配置、插件市场、订阅、日志
     ├── 适配器      QQ 官方 / OneBot 11 的连接与收发
     └── 插件运行时   加载 .so，把事件分发给插件
           │
           ▼
      PostgreSQL
```

**事件是怎么流动的**（以一条群消息为例）：

1. 适配器从平台收到消息；
2. 框架把不同平台的消息**归一化成统一事件**，插件只面对这一种结构，不需要为每个平台写一套代码；
3. 事件按优先级依次交给该机器人已启用的插件，插件可以选择回复、改写、拦截或什么都不做；
4. 插件要发消息时，调用**统一的发送接口**，由适配器翻译成对应平台的格式发出去。

插件开发者只需要理解第 2–4 步，不用关心平台差异。

## 能做什么

- **接机器人**：QQ 官方机器人（Webhook 或 WebSocket 网关）与 OneBot 11（反向 WebSocket）。创建后立即生效，不用重启服务。
- **装插件**：从插件市场一键安装到某台机器人，可启停、可调优先级、可单独开关拦截能力。
- **管社群**：内置的群管插件提供违禁词、链接/卡片/转发拦截、刷屏检测、禁言踢人、入群验证与入群审批。
- **看数据**：机器人状态、消息记录、运行日志、服务器监控都在网页里，不需要登服务器看后台日志。
- **做定制**：插件可以用 C++ 写，自带 Web 配置面板，也能调用平台的禁言、踢人、审批等能力。
- **商业化**（如果你对外提供服务）：套餐订阅、卡密兑换、余额充值、支付对接。

## 适合谁

**适合你，如果：**

- 想自己完全掌控机器人和数据，不喜欢把机器人托管在别人的平台上；
- 需要同时管理多台机器人，或者要给不同的人分配不同的机器人；
- 有定制需求，愿意写（或找人写）C++ 插件；
- 想要一套开箱即用的社群管理能力，而不是从零拼插件。

**可能不适合你，如果：**

- 只想跑一个单群小机器人、且不想碰服务器 —— 更轻量的本地框架会更省事；
- 只接非 QQ 平台 —— 本框架目前的适配器专注 QQ。

## 和其他机器人框架的区别

| 维度 | 常见做法 | Xiaoyi_QQ_V4 的选择 |
| --- | --- | --- |
| 部署 | 需要 Python 运行时 + 若干依赖包 | 单个二进制，除数据库外无依赖 |
| 插件 | 脚本语言，改完要重启 | C++ 动态库，只增不改的稳定接口 |
| 多机器人 | 一个实例跑一个机器人 | 一个实例管多台，控制台里按机器人隔离数据 |
| 插件配置 | 改配置文件 | 插件自带网页面板，在控制台里点开就用 |
| 平台差异 | 插件里写 `if 平台 == ...` | 框架统一成一套事件与调用接口 |

代价也要说清楚：**插件是编译型的**，改一行代码要重新编译再上传（可以用在线云编译服务）；并且由于是原生程序，插件写崩溃时会影响框架进程，写插件时要注意异常处理。
