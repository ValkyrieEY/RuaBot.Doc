# 在线更新

> **你会学到**：怎么在后台一键升级到新版本，更新后自动重启。

V3 内置**在线更新**机制，小版本升级无需 SSH 登录服务器、无需重新部署。

## 检测更新

登录管理后台 → **系统更新**：

1. 点击「检测更新」，系统向云端查询最新版本。
2. 如有新版本，会显示版本号、更新内容、更新文件数量和大小。
3. 确认后点击「立即更新」。

## 更新过程

更新会：

1. **增量下载**更新包（只下载变化的文件）。
2. 替换变化的文件。
3. 如新版本附带 SQL 迁移脚本，自动执行。
4. **自动重启**服务，加载新代码。

::: tip 更新期间短暂中断
更新完成后服务会自动重启，浏览器可能短暂断开（几秒），属正常现象。重启完成后刷新页面即可。
:::

## 自动重启

更新后必须重启才能加载新代码（尤其是编译保护的模块）。V3 支持：

- **自动重启**：更新完成后，服务在几秒后自动重启（默认开启）。
- **手动重启**：如果你关闭了自动重启，需要手动执行 `docker compose restart`。

::: warning 为什么必须重启
受保护的代码模块在进程启动时加载，运行中替换文件不会立即生效。重启是让新代码生效的必要步骤。
:::

## 版本号

- 系统版本号在后台首页和系统更新页可见。
- 云端返回的版本号 > 本地版本号时，提示有更新。
- 版本号采用语义化版本（如 `3.0.5`）。

## 更新失败怎么办

- **网络问题**：检查服务器能否访问授权云（更新包从云端下载）。
- **磁盘空间不足**：清理后重试。
- **权限问题**：确认部署目录可写（Docker volume 挂载方式天然可写）。

更新失败不会破坏现有系统——文件替换是原子操作，失败时保持旧版本运行。

## 大版本升级

跨大版本（如 3.x → 4.x）或镜像本身变更时，建议用 `install.sh` 重新部署而非在线更新：

- 数据在 volume 持久化，重新部署不丢数据。
- 详见 [Docker 部署 · 升级](./docker#升级部署)。
